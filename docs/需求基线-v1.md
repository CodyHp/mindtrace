# ObsTracker 需求基线 v1

> 状态：需求对齐稿（draft），随对话随时修订。
> 本文件是对「事件追踪看板插件」需求对齐的固化结果，非最终 PRD。

---

## 1. 一句话定位

一个**本地优先、零打扰**的 Obsidian「注意力画像」插件：后台自动记录你在每篇笔记上的停留与写作，按 folder 递归归集到业务分类，产出「时段 × 主题」的规律报表。所有元数据仅本地存放、不上传、不联网、不读笔记内容、不引 LLM。

---

## 2. 目标用户与核心场景

- 目标用户：Obsidian 深度用户，vault 目录天然按业务分类，对写作心流敏感。
- 核心诉求：看懂「我把时间花在了哪些内容上」，而非「我又打卡了几分钟」。
- 体验红线：**心流优先** —— 后台自动记录，零弹窗、零强制手动操作、零打断。

---

## 3. 核心功能

### 3.1 数据采集（本插件重中之重）

后台自动采集用户操作数据，目标是「完善地记录」，报表粒度后期都可调。

- 事件流记录：打开 / 切换 / 关闭笔记、活跃心跳、编辑操作、字符增量。
- 每条事件携带：时间戳、笔记路径、笔记标题、编辑模式（源码 / 预览 / 阅读）。
- 剔除空闲 / 锁屏 / 休眠时段，不计入活跃时长。
- 弱推断「阅读态 vs 写作态」：依据编辑密度 + 编辑模式 + 交互间隔，接受误差、不求精准。
- 存储：append-only 本地文件，不上传、不联网、不读取/存储笔记正文内容。

### 3.2 内容分类：folder 递归累积

- 分类依据**仅 folder**，不使用 tag / 双链 / 内容语义。
- 时长沿目录树**逐级递归累积**：`哲学/西方/康德` 一篇的时长，同时计入「哲学」「西方」「康德」三级；父目录时长 = 其下所有子目录与文件之和。
- 每一级 folder 均可独立出榜、独立下钻。

### 3.3 字数：双指标

- 本次写作**新增字数**（增量，衡量产出）。
- 文档**总字数快照**（衡量篇幅状态）。
- 两者都记录。

### 3.4 报表：独立 dashboard 笔记（形态 B）

- 报表以**独立 Obsidian 笔记**形式产出：可版本管理、可被其它插件（Dataview 等）读取。
- 明细时间线：几点到几点打开了哪篇笔记。
- 聚合统计：日 / 周 / 月；folder 时长排行、阅读 vs 写作占比、字数趋势。
- 规律洞察：时段 × 主题矩阵（24 小时小时粒度，用户可自行归并为上午/下午）、星期分布、写作高峰、心流时段。
- 输出形式：**图表为主**，暂不引入「一句话人话结论」模板（人话需要 LLM 或特定模板，较复杂）。

---

## 4. 已拍板的约束（决策记录）

| 决策点 | 结论 |
|---|---|
| 内容分类依据 | 仅 folder |
| 时长归集 | 沿目录树递归累积（父 = 子之和，各级独立可查） |
| 阅读 / 写作区分 | 弱推断，接受误差，无手动声明 |
| 体验原则 | 心流优先，零打扰 |
| 洞察层 | 纯规则统计，不引 LLM（除非未来做内容语义分析） |
| 隐私 | 所有元数据仅本地，绝不上传、不联网 |
| 报表形态 | 独立 dashboard 笔记（B） |
| 字数 | 新增字数 + 总字数快照（C，双指标） |
| 报表输出 | 图表为主（A） |
| 手动纠错单条记录 | 不做 |
| 报表周期 / 时段粒度 | 日/周/月 + 24h 小时粒度（后期可调，非本期重点） |

---

## 5. 非目标（V1 明确不做）

- 按 tag / 双链 / 内容语义分类
- LLM 语义分析、自动主题聚类
- 手动纠错 / 事后修改单条记录归属
- 「一句话人话结论」模板
- 任何形式的上传 / 同步 / 云端 / 账号 / 遥测
- 读取或存储笔记正文内容

## 6. 数据模型与采集参数（已拍板）

### 6.1 事件类型

> 注：早期方案为 7 类事件，经采集层设计收敛为 **2 类落盘事件**（`session` + `edit`），详见《采集层设计-v1.md》第 2 节。下表为收敛后的最终落盘事件。

| 落盘事件 | 含义 | 关键字段 |
|---|---|---|
| `session` | 一段连续活跃停留 | ts, endTs, notePath, noteTitle, mode, activeSeconds, endedBy, totalChars, totalWords |
| `edit` | 编辑增量 | ts, notePath, charDelta, wordDelta |

收敛关系：`note_open` / `note_switch` / `note_close` → session 起止与 `endedBy`；`heartbeat` 不落盘（仅内存累积）；`idle` / `app_blur` → `endedBy`。

### 6.2 采集阈值（默认值，均做成设置项）

- 心跳间隔：**30 秒**
- 空闲判定：无交互 **3 分钟** → `idle`，该段不计入活跃
- 窗口失焦（`app_blur`）：**立即暂停计时**

### 6.3 阅读/写作弱推断规则

- 以 **5 分钟为固定分片**，片内累计 `charDelta` 超过阈值（默认 20 字）→ 判「写作」，否则「阅读」。
- 叠加 `mode` 修正：`preview` 偏向「阅读」。
- 规则透明、可解释、可调；详细算法见《报表层设计-v1.md》第 3 节。

### 6.4 存储位置与格式

- 位置：vault 根下**可配置目录**，默认 `.obstracker/`（用户可改）。
- 格式：**append-only JSONL，按天分文件**（`events-YYYY-MM-DD.jsonl`）。
- 插件自身配置（排除路径、阈值等）走 Obsidian 官方 `data.json`，与原始事件分离。
- 不塞进 `.obsidian/plugins/`，避免重装插件丢数据。
